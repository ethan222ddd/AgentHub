# 可自訂工作流程範本（v0.12.0）

## 使用

1. 開啟專案聊天室，先在「團隊」設定成員。專案須啟用自動管理工作區，三家 Runtime 的安裝／登入／模型與權限沿用既有設定。
2. 點上方「流程」。左側選範本，在「套用與進度」把範本角色指派給已啟用的團隊成員，再填寫需求、啟動。聊天輸入框的文字會作為需求初稿；範本啟動不需要每次手動 @Agent。
3. 聊天室顯示簡潔進度列；點「查看流程」查看每一步與回修次數。詳細工具、批准、Diff、測試仍在原有活動／變更面板。
4. 可暫停、取消或檢查後繼續。停止聊天室會暫停流程；「繼續聊天室」只解除聊天室停止，流程仍要從流程面板明確繼續。App 重啟後流程暫停，不會自動重播任務。

## 內建範本

- **實作 → 審查 → 回修 → 測試整合**：預設 Codex 實作、Claude 唯讀審查。退件後由原實作者修正，原審查者重新審查新快照；預設每個實作步驟最多回修兩次。批准後由 Host 測試確切整合快照，再走原有安全合併。
- **規格契約 → 平行實作 → 交叉審查**：預設 AGY 建立並透過 `publish_artifact` 發布契約。完成版本沒有相應產物就停止，不把普通文字當成交接成功。Codex／Claude 收到不可變 Artifact ID、Commit 和檔案清單，使用 `read_artifact` 取得內容，在獨立 Worktree 平行實作，再交換審查。全部通過後逐份測試、整合；後一份測試包含前一份已整合的內容。

契約步驟只發布產物，不自動合併規格分支。Worktree 不會自動同步；實作者須透過原生檔案工具把需要的契約檔案放入自己的工作區。這是明確的產物交接，沒有把其他工作區路徑當成共享目錄。三家仍由各自的真實 Adapter 執行，沒有新增聊天模型替代品。

## 自訂與編輯

「新增範本」會以常用流程起步。也可編輯內建範本或「另存副本」，沒有固定範本數量。可編輯：

- 名稱、說明、每個實作步驟的回修上限（0–5）。
- 角色名稱與預設供應商；真正的 Agent 實例在套用時綁定，供應商只是預設選擇。使用同一家供應商的不同實例也可，審查者須與實作者不同實例。
- 最多 24 個步驟：代理任務（含規格／實作）、唯讀審查、Host 測試整合。
- 步驟角色、額外指示、先決步驟、審查／整合的來源、必須發布的產物與所需產物來源。

沒有依賴的代理步驟可平行執行，仍受現有每個 Agent／工作區鎖、最大並發、回合數、用量與逾時限制。上下移動只調整顯示順序，真正執行順序由依賴決定。依賴循環、來源缺失、沒有對應審查的整合等會拒絕儲存。審查必須回傳 `submit_review` 結構化結果；自然語言「看起來沒問題」不算批准。

整合是 Host 既有安全流程，不接受額外 Shell 指令或用自然語言假裝條件成立；測試入口沿用專案既有的測試政策。只有靜態檢查時仍明確標示，不宣稱功能測試。原有全域指定 Reviewer gate 若更嚴格，仍須滿足，不會被範本關閉。

編輯後先儲存，才可套用。每次啟動會保存完整範本與角色綁定副本；修改或刪除範本不影響正在執行的流程／歷史紀錄。範本存於本機 SQLite，隨資料庫備份、還原。刪除範本需按兩次確認。

## 停止與恢復的邊界

為避免獨立任務悄悄改動已審查的分支，同一專案同時只允許一條未結束流程；期間新的 Agent 派工、手動合併／工作區變更或手動 Review 會拒絕。本機筆記仍可保存。流程內不能額外 `assign_task` 或啟動範本外 Agent；產物讀寫、公開進度及原生檔案／工具權限仍可用。

未完成的原生任務只有使用者明確「檢查後繼續」才建立新嘗試，保留 attempt 與流程關聯。Runtime 已完成、只剩快照或整合失敗時，只重試 Host 階段，不重跑 Agent。未發布契約、審查沒有結構化結果、超出回修預算或外部修改造成版本不符時，會顯示原因；必要時取消此流程、調整範本／需求後重開，沒有無限自動重試。

多份整合採逐份安全測試與合併，並非整條流程的原子交易。後一份失敗時，前一份已通過的合併保留，顯示待處理狀態，沒有自動 Hard Reset。可檢查主專案與 Diff 後重試剩餘整合。規格產物目前為文字檔案，沿用既有大小及敏感路徑限制；流程需求欄位為文字，沒有新增範本附件編輯器。

## 資料相容性與驗證

Migration 8 增加 `workflow_templates`、`workflow_runs`。內建範本只在遷移時建立一次；使用者刪除後不會每次啟動又出現。舊版 App 會拒絕開啟 Schema 8，避免舊排程器把流程任務當成一般任務整合；升級前先備份。

本階段僅跑範本、任務依賴／恢復、Review gate、SQLite／備份及單一 Electron 範本 E2E。代理用受控 Fixture Adapter，Git、Worktree、結構化產物、快照、Review gate 與快照測試實際執行；測試沙盒是明確的 Fixture，不宣稱正式 OS 沙盒驗收。打包版 E2E 驗證 UI／IPC／SQLite 與重啟，不產生模型回合。未重跑三家付費 Live 或整套回歸，最終範圍見 release/0.12.0/WORKFLOW_VALIDATION.json。

主要修改：`src/shared/{types,schemas,workflows}.ts`、`src/main/{workflows/service,database/store,database/backup,orchestrator/orchestrator,git/automatic,ipc/handlers,index}.ts`、`src/renderer/{App.tsx,styles.css,features/WorkflowEditor.tsx}`；測試為 `tests/workflow-templates.test.ts`、`tests/e2e/workflow-templates.spec.ts` 與相關既有 gate／持久化測試。
